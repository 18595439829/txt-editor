## ✅ 修复方案

### 修复内容

**文件**: editor.html (第 747-772 行)

```javascript
// ✅ 修复后的删除文件逻辑
deleteFileBtn.addEventListener("click", async () => {
  if (!confirm("确定要删除此文件吗？此操作不可撤销。")) return;
  try {
    const currentFileId = fileManager.currentFileId;

    // ✅ 关键修复 #1: 获取该文件的所有缓存图片
    const fileImages = await imageCache.getFileImages(currentFileId);

    // ✅ 关键修复 #2: 逐个删除这些缓存
    for (const img of fileImages) {
      await imageCache.deleteImage(img.id);
    }

    // ✅ 关键修复 #3: 记录日志
    if (fileImages.length > 0) {
      console.log(`已删除 ${fileImages.length} 个关联缓存`);
    }

    // 删除文件
    await fileManager.deleteFile(currentFileId);

    // ✅ 关键修复 #4: 更新 UI
    await refreshFilesList();
    await updateGlobalCacheUI();
    await updateFileCacheUI();

    // ✅ 关键修复 #5: 清晰的用户提示
    showToast("文件及其关联缓存已删除", "success");
  } catch (error) {
    showToast("删除失败: " + error.message, "error");
  }
});
```

### 五个关键改进

1. **获取缓存** - `imageCache.getFileImages(fileId)`
2. **删除缓存** - 循环 `deleteImage()`
3. **记录日志** - 便于调试
4. **更新 UI** - 反映缓存变化
5. **优化提示** - "文件及其关联缓存已删除"

## 📝 技术说明

### 使用的方法

1. **getFileImages(fileId)**
   - 获取某个文件的所有缓存图片

2. **deleteImage(id)**
   - 删除单个缓存（同时删除 IndexedDB 和 Cache API）

3. **updateGlobalCacheUI()**
   - 刷新全局缓存 UI 显示

4. **updateFileCacheUI()**
   - 刷新文件缓存 UI 显示

### 为什么要逐个删除

- IndexedDB 没有"按条件批量删除"的方法
- 必须逐个操作每个缓存记录
- 同时清理 IndexedDB 和 Cache API 两个存储
